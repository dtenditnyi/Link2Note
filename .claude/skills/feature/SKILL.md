Задача: **$ARGUMENTS**

Работай строго по @docs/WORKFLOW.md, шаг за шагом, не пропуская шагов. Контекст проекта: @CLAUDE.md, этапы: @docs/PLAN.md.

1. **Понять задачу.** Перескажи её в 1–2 предложениях. Неясно или есть несколько разумных вариантов — спроси через AskUserQuestion.
2. **Исследовать** (ничего не меняя):
   - код проекта: что есть, что переиспользовать, что сломается;
   - Context7: API используемых библиотек (aiogram 3, google-genai, APScheduler, yt-dlp …), не по памяти;
   - WebSearch: как это обычно делают и известные проблемы — 3–5 находок со ссылками;
   - чего не хватает: edge cases, ошибки, безопасность, улучшения сверх запроса (предложить, не делать).
3. **План и критерии приёмки.** Файлы и порядок, что нужно от меня, список проверяемых критериев приёмки. Для крупной функции — спецификация в `docs/specs/<название>.md`. **Выбери вариант сам и запиши решение в DECISIONS.md.**
4. **Сначала тесты** по критериям (сеть/LLM/git мокаются). Запусти — они должны падать по правильной причине. Покажи вывод.
5. **Код** модуль за модулем, после каждого — `uv run pytest -q tests/<файл>`. Не подгоняй тесты под код; если тест неверный — объясни и только потом правь.
6. **Проверка:** `uv run pytest -q` и `uv run ruff check .` (покажи вывод), затем ревью diff субагентом против критериев из шага 3; исправь реальные проблемы. Скажи, что проверить руками и какой командой.
7. **Завершение:** обнови `docs/PLAN.md` и `CLAUDE.md`, если нужно. Коммить сам при зелёных тестах + ruff + ревью, сообщение на английском.

Правила из CLAUDE.md действуют всегда: фильтр `OWNER_ID`, секреты только через `.env` → `config.py`, не делать функционал следующих этапов без запроса.
