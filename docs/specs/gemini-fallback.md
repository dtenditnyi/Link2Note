# Gemini перегружен: запасная модель и отложенные повторы

Статус: **план принят 09.11.2026** (с двумя добавками ниже). Ветка `feature/stage-2`, в `main` не вливать.

## Задача
Когда Gemini отвечает 503 (перегружен) или 429 (лимит) даже после встроенных повторов SDK, бот делает одну попытку на запасной модели (`GEMINI_FALLBACK_MODEL`). Если и она недоступна, задача не падает: она откладывается в очереди на 5, 15, 30 минут (максимум 3 раза), и бот пишет «Gemini перегружен, попробую снова в HH:MM». Плюс после перезапуска приходит отдельное сообщение вместо статуса «⏳», который сразу перезаписывается.

## Решения владельца (09.11.2026)
- Запасная модель по умолчанию — `gemini-3.7-flash`.
- Дневная квота (429 с `quotaId …PerDay…` у обеих моделей) → задача ждёт до сброса квоты (полночь по тихоокеанскому времени + 5 мин, это ~10:05 по Бухаресту). Это не считается одним из 3 откладываний.

## Исследование
**Какие модели доступны** (`client.models.list()` с ключом из `.env`, 09.11.2026): `generateContent` есть у gemini-2.5-flash/-pro/-flash-lite, 3.1-flash-lite, 3.5-flash, 3.5-flash-lite, 3.6-flash, 3.7-flash, **3.8-flash (основная)**, omni-flash-preview, 4-argon и у image-моделей. Видео на вход принимают (проверено через `count_tokens` на YouTube-ссылке, без генерации): 3.8-flash, 3.7-flash, 3.6-flash, 3.5-flash, 3.5-flash-lite, 3.1-flash-lite. Качество конспекта у запасной модели покажет только живой прогон.

**Код.**
- `DigestLLM._generate`: 429 → `DigestError("Лимит…")`, 5xx → `DigestError("недоступен")`. Задача уходит в `failed`. Запасной модели нет.
- SDK уже повторяет 429/503: `HttpRetryOptions(attempts=3)` — это 3 запроса до ошибки.
- Видео через Files API: загруженный файл подходит любой модели — для запасной модели второй раз загружать не нужно.
- `link_jobs` в локальной базе уже создана без новых колонок → нужна миграция (`ALTER TABLE ADD COLUMN`).
- Сообщение «⏳ После перезапуска…»: `main.py` сначала вызывает `restore_jobs`, сразу затем запускается воркер, и первая задача за миллисекунды меняет статус на «🧠…». К тому же правка сообщения в Telegram не даёт уведомления.
- `services/intent.py` (голосовые и текстовые напоминания) тоже использует `GEMINI_MODEL`; ошибки Gemini там пробрасываются как есть, и хендлеры отвечают «Не удалось обработать голосовое» / «Не получилось разобрать напоминание». Повторов SDK там нет.

**Библиотеки** (google-genai 3.0.0, исходники и Context7).
- `errors.APIError`: `code`, `status`, `message`, `details` (это весь JSON ответа). У 429 в `details.error.details[]` есть `QuotaFailure.violations[].quotaId` и `RetryInfo.retryDelay`.
- `HttpRetryOptions`: `attempts` (включая первый запрос), экспоненциальная пауза 1 → 60 с, статусы для повторов задаются явно.

**Интернет.**
- [Форум Gemini: 503 «model is overloaded» у платных тоже](https://discuss.ai.google.dev/t/im-paid-but-503-error-the-model-is-overloaded-please-try-again-later/105581) и [перегрузка у разных моделей разная](https://discuss.ai.google.dev/t/gemini-2-5-flash-pro-models-frequently-overloaded-needs-attention/105505) — обычный обход: повторы с паузой и запасная модель (мощность у каждой модели своя).
- [503-повторы, вероятно, считаются в квоту RPM/RPD](https://discuss.ai.google.dev/t/503-retries-are-counted-against-the-rpd-rpm-quota-making-the-effective-quota-a-fraction-of-whats-shown/144053) — не множить повторы без нужды (не подтверждено Google).
- [429 при ожидании retryDelay](https://discuss.ai.google.dev/t/429-errors-despite-waiting-after-retrydelay/96899) и [разбор 429](https://inventivehq.com/knowledge-base/gemini/gemini-429-resource-exhausted) — поминутную и дневную квоту различают по `quotaId`; `retryDelay` для дневной вводит в заблуждение. Квота считается на проект, а не на ключ.

## Чего не хватало (включено)
1. **Какие ошибки — «перегружен»:** 429 и все 5xx (500/502/503/504) после повторов SDK. Другие 4xx (400 «плохое видео», 403 ключ) → сразу `failed`, без запасной модели: повтор не поможет.
2. **Миграция базы:** у `link_jobs` появляются колонки `run_after`, `defers`, `quota_waits`; на старой базе они добавляются при `init()`, старые строки сохраняются.
3. **Откладывание без блокировки воркера:** отложенная задача не держит очередь — остальные ссылки обрабатываются. Задача возвращается в очередь по таймеру (`asyncio`), а после перезапуска — через `restore_jobs` по `run_after`.
4. **Откладывание — не падение:** попытка не засчитывается в лимит «3 падения подряд» (как при Ctrl+C).
5. **Ограничение для дневной квоты:** ждать сброса — не больше 1 раза на задачу. Если и после сброса дневной лимит — `failed` (иначе задача может зациклиться).
6. **Сообщение после перезапуска:** новое сообщение (с уведомлением) в каждый чат, где есть задачи: «🔄 Бот перезапущен — вернул в очередь ссылок: N» (+ «ждут Gemini: K, ближайшая в HH:MM»). Статусы самих задач идут как раньше.
7. **Время HH:MM** — в часовом поясе бота (`config.py`). Часовой пояс сброса квоты (`America/Los_Angeles`) — тоже константа в `config.py`.
8. **CLI:** запасную модель тоже использует; откладывать некуда, поэтому при перегрузке — понятная ошибка и код 1.

## План (файлы и порядок)
1. `config.py`: `gemini_fallback_model: str = "gemini-3.7-flash"` (пусто — выключена; совпадает с основной — выключена), константа `QUOTA_RESET_TZ = "America/Los_Angeles"`.
2. `digest/errors.py`: `GeminiBusy(DigestError)` с флагом `daily: bool`.
3. `digest/llm.py`: `DigestLLM(..., fallback_model="")`; `_generate` пробует основную, при «перегружен» — один раз запасную (с тем же списком частей запроса, видео-файл не перезагружается); обе перегружены → `GeminiBusy(daily=обе 429 с PerDay)`. В лог — какая модель ответила.
4. `database.py`: колонки и миграция; `LinkJob` + `run_after`, `defers`, `quota_waits`; `postpone_job(id, run_after, *, daily)` (счётчик +1, попытку возвращаем).
5. `digest/worker.py`: `Job` + `defers`, `quota_waits`; `Postponer` (`later(job, at)`, `close()`); в `process_job` добавляются `clock` и `postponer`; обработка `GeminiBusy`: задержки `[5, 15, 30]` мин → сообщение, либо дневная квота → до сброса, либо `failed`. `restore_jobs` учитывает `run_after` и возвращает сводку для сообщения после перезапуска.
6. `main.py`: запасная модель, `clock`, `Postponer` (закрывается при остановке), сообщение «🔄 Бот перезапущен…».
7. `digest/cli.py`: запасная модель.
8. `CLAUDE.md` (`.env`: `GEMINI_FALLBACK_MODEL`), `docs/PLAN.md`.

Тесты (сначала, красные): `test_schema_llm.py` (мок 503/429 у `generate_content` по моделям), `test_database.py`, `test_worker.py` (фейковые часы, `Postponer` с мгновенным таймером), `test_config.py`, `test_main.py`/`test_cli.py` при необходимости.

## Что нужно от владельца
Ничего. Для ручной проверки — `GEMINI_MODEL` на несуществующую/перегруженную модель или дождаться 503; см. «Ручная проверка».

## Критерии приёмки
**LLM (Gemini замокан)**
- G1. Основная ответила → запасная не вызывалась.
- G2. Основная 503 (после повторов SDK) → один вызов запасной с тем же содержимым запроса; её ответ — результат. Для видео-файла: upload один раз, `files.delete` один раз.
- G3. Основная 429 поминутный → запасная. Основная 500/502/504 → запасная.
- G4. Основная 400/403 → `DigestError` сразу, запасная не вызывается.
- G5. Обе 503 → `GeminiBusy(daily=False)`. Обе 429 с `quotaId …PerDay…` → `GeminiBusy(daily=True)`. Одна дневная, другая 503 → `daily=False`.
- G6. Запасная не задана или равна основной → одна модель; при 503 сразу `GeminiBusy`.
- G7. Запасная ответила 400 → `DigestError` (не `GeminiBusy`).

**База**
- B1. `init()` на базе со старой `link_jobs` добавляет `run_after`, `defers`, `quota_waits`; старые строки на месте.
- B2. `postpone_job` ставит `run_after` (UTC), увеличивает нужный счётчик, возвращает попытку (`attempts` не растёт); задача остаётся `pending`.

**Воркер (часы и таймер фейковые)**
- Q1. `GeminiBusy` при `defers=0/1/2` → задача отложена на 5/15/30 мин: статус «⏳ Gemini перегружен, попробую снова в HH:MM (повтор k из 3)» во времени бота, `Postponer.later` с этим временем, в базе `pending` + `run_after`.
- Q2. `GeminiBusy` при `defers=3` → `failed`, «❌ Не получилось: Gemini перегружен уже ~50 минут — пришли ссылку позже».
- Q3. `GeminiBusy(daily=True)`, `quota_waits=0` → отложено до полуночи PT + 5 мин (например, при «сейчас» 09.11 14:00 по Бухаресту → 10.11 10:05), текст «Лимит Gemini на сегодня исчерпан — попробую снова в 10:05». Счётчик `defers` не меняется. При `quota_waits=1` → `failed`.
- Q4. Отложенная задача не блокирует очередь: следующая задача обрабатывается сразу.
- Q5. `Postponer.later` возвращает задачу в очередь в нужное время; `close()` отменяет таймеры (задачи остаются в базе `pending`).
- Q6. Повторная обработка отложенной задачи после успеха → обычная заметка, `done`.
- W1–W9 предыдущих этапов зелёные.

**Перезапуск**
- R1. `restore_jobs`: задача с `run_after` в будущем → `Postponer.later`, не сразу в очередь, её статус не перезаписывается; с `run_after` в прошлом или без него → сразу в очередь.
- R2. После восстановления в каждый чат с задачами приходит **новое** сообщение «🔄 Бот перезапущен — вернул в очередь ссылок: N» (+ «ждут Gemini: K, ближайшая в HH:MM», если есть отложенные). Нет задач → сообщения нет.

**Прочее**
- C1. `GEMINI_FALLBACK_MODEL` по умолчанию `gemini-3.7-flash`, пустое значение → выключено.
- K1. CLI использует запасную; при `GeminiBusy` — «❌ …» и код 1.
- K2. `uv run pytest -q` и `uv run ruff check .` — зелёные.

## Ручная проверка
Вызвать 503 по желанию нельзя (неверная модель даёт 404, неверный ключ — 400), поэтому откладывание проверяют тесты, а вручную — по факту:
1. Когда основная модель снова ответит 503 (как с Википедией), в логе будет «gemini-3.8-flash: 503 → запасная gemini-3.7-flash» и появится заметка.
2. Если перегружены обе: статус «⏳ Gemini перегружен, попробую снова в HH:MM», в это время задача сама продолжится.
3. Перезапуск, пока задача отложена → новое сообщение «🔄 Бот перезапущен…», статус с временем не перезаписан.
4. Перезапуск с обычной задачей в очереди → то же новое сообщение (оно приходит с уведомлением).

## Добавки владельца (09.11.2026)
1. **Напоминания** (`services/intent.py`): при 429/5xx — одна попытка на `GEMINI_FALLBACK_MODEL`, без откладывания. Если и она недоступна — ошибка пробрасывается как раньше (хендлеры: запасной разбор времени / «Повторить»).
2. **Какая модель сделала конспект:** строка в логе и поле `model:` во frontmatter заметки (например `model: gemini-3.7-flash`).

Как устроено: `DigestLLM.digest_*` возвращают `Digested(digest, model)` вместо голого `Digest` — модель не добавляется в схему ответа Gemini. Общая проверка «перегружен» (429 или 5xx) — `services/gemini_errors.py`, её используют и `digest/llm.py`, и `services/intent.py`.

**Критерии приёмки (добавки)**
- I1. Напоминание: основная 503 или 429 → один вызов запасной; её ответ разобран как обычно.
- I2. Основная 400 → запасная не вызывается, ошибка та же, что раньше.
- I3. Обе недоступны → исключение запасной модели пробрасывается (хендлеры не меняются); запасной нет или она равна основной → один вызов.
- M1. Во frontmatter `model: <имя модели>` (после `confidence`); пустое имя модели → поля нет (golden YouTube не меняется).
- M2. Конспект от запасной модели → `model: gemini-3.7-flash`; в логе строка с именем модели, сделавшей конспект.

## После ревью (09.11.2026)
- Статус `postponed` выставляется до правки сообщения «⏳ …» (база и таймер — тоже до неё): остановка бота во время этой правки больше не помечает отложенную задачу `failed`. При остановке сначала отменяется воркер, потом таймеры `Postponer`.
- SDK повторяет только 429/503 (как раньше). На 500/502/504 запасная модель пробуется, но откладывается задача только при 429/503 хотя бы у одной модели: 500 на видео часто постоянная (кодек, длина), и откладывание сожгло бы ~24 запроса за 50 минут. Только 500/502/504 у обеих → «Gemini сейчас недоступен (ошибка N)», `failed`.
- Сброс дневной квоты: ошибка с 00:00 до 00:05 PT → ждём сегодняшние 00:05, а не завтрашние.
- Сводка после перезапуска: «🔄 Бот перезапущен — вернул в очередь ссылок: N, ждут Gemini: K (ближайшая в HH:MM)» (R2).
- Не делал: при дневной квоте основной модели SDK всё равно делает 3 попытки на ней перед запасной — повторы SDK не отключить выборочно; для личного использования приемлемо.

## Позже (09.11.2026): модели по умолчанию — Lite
На free tier у `gemini-3.8-flash` всего 20 запросов в сутки (упёрлись: RPD 22/20), у `gemini-3.5-flash-lite` и `gemini-3.1-flash-lite` — 500 в сутки и 15 в минуту. Решение владельца: `GEMINI_MODEL=gemini-3.5-flash-lite`, `GEMINI_FALLBACK_MODEL=gemini-3.1-flash-lite` (обе принимают видео — проверено `count_tokens` выше).
