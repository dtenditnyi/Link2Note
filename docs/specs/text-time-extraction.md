# Время из текста напоминания

Статус: **реализовано, ждёт ручной проверки**.

## Задача
«через 2 минуты напомни про лимиты клода» → бот сам находит время (через 2 минуты), не спрашивает его второй раз, задача — «лимиты клода». Работает в шаге `/new` «о чём напомнить» и в свободном тексте со словом «напомни». После времени — как обычно, вопрос о повторе кнопками.

## Решения владельца (09.11.2026)
- Где: `/new` **и** свободный текст, если в нём есть «напомни/напомнить/напомните». Без этого слова текст по-прежнему тихо уходит в контекст для голосовых.
- После найденного времени: вопрос «Повторять?» кнопками (как сейчас).
- Способ: **правила (regex), если не нашлось — Gemini** (только для свободного текста со словом «напомни»).

## Исследование
- `services/timeparse.py` разбирает только строку **целиком** (`fullmatch`) — для фразы с задачей не подходит; грамматику (единицы, «сегодня/завтра», HH:MM, даты) можно переиспользовать для поиска внутри текста.
- `dateparser.search_dates` — открытый баг именно на «через 2 часа» по-русски ([issue #706](https://github-users.yhajoa.workers.dev/scrapinghub/dateparser/issues/706)); в документации поиск дат в тексте назван ограниченным ([docs](https://dateparser.readthedocs.io/)). Тянуть зависимость ради этого не стоит.
- Natasha — подтверждённой поддержки относительного времени («через 2 часа») не нашёл.
- `services/intent.IntentParser` уже умеет текст → {task, remind_at, repeat} через Gemini — переиспользуем как запасной путь (подпись «Голосовая команда» → параметр).

## Чего не хватает (предлагаю включить)
- «через минуту / через час / через день / через неделю» без числа и «через полчаса» — частые формы, regex их сейчас не понимает (T6).
- Пустая задача после вырезания времени («напомни через 5 минут») → бот спрашивает «О чём напомнить?», время уже запомнено.
- Время в прошлом («сегодня 10:00», когда уже 12:00) → понятная ошибка, а не тихое создание.

## План
1. `services/timeparse.py`: `extract_time(text, now) -> (datetime, остаток_текста) | None` — ищет поддерживаемые форматы в любом месте фразы, приоритет у более длинного совпадения («завтра в 9:00» целиком, а не только «9:00»); прошлое → `ValueError`. + формы без числа и «полчаса» (T6) — и в `parse_reminder_time`.
2. `services/text_reminder.py`: `has_trigger(text)`; `clean_task(rest)` — убирает «напомни(ть) (мне)», ведущие «про/о/об/что/чтобы», лишние знаки и пробелы; `parse_text_reminder(text, now) -> TextReminder(task, remind_at | None)`.
3. `services/intent.py`: параметр `kind` («Голосовая команда» / «Текстовая команда») в `parse`.
4. `handlers/reminders.py`:
   - `on_task` (шаг `/new`): если в тексте есть время → сохранить задачу и время, сразу «Напомню … Повторять?»; если задача пустая — переспросить задачу; если время уже есть в FSM (пришли из «напомни через 5 минут») — после задачи сразу повтор.
   - новый `on_free_text` (без состояния, текст со словом «напомни»): regex → иначе Gemini (статус «🤔 Разбираю…») → тот же вопрос о повторе; Gemini не понял → подсказка с форматами и `/new`.
5. Роутинг: `on_free_text` в роутере `reminders` (раньше `voice`/`context`); фильтр — `StateFilter(None)` + слово-триггер; текст без триггера остаётся контекстом.
6. Тесты сначала (красные): `test_timeparse.py`, `test_text_reminder.py`, `test_reminders_handlers.py`, `test_intent.py`, `test_main.py` (через `dp.feed_update`).
7. Обновить `HELP` в `handlers/basic.py`, PLAN.md, спецификацию.

## Критерии приёмки
**Разбор (без сети)**
- E1. «через 2 минуты напомни про лимиты клода» → время now+2 мин, задача «лимиты клода».
- E2. «напомни про лимиты клода через 2 минуты» → то же (время в конце).
- E3. «завтра в 9:00 напомни позвонить маме» → завтра 09:00, «позвонить маме» (длинное совпадение, не только «9:00»).
- E4. «напомни мне что надо оплатить интернет 2026-11-20 10:00» → 20.11 10:00, «надо оплатить интернет».
- E5. «напомни, через 1 ч 30 мин, выключить духовку» → now+1:30, «выключить духовку» (запятые убраны).
- E6. «через час напомни размяться», «через полчаса напомни про чай», «через минуту …» → +60 / +30 / +1 мин (T6).
- E7. «напомни через 5 минут» → время есть, задача пустая.
- E8. «сегодня 10:00 напомни …» при now=12:00 → ошибка «прошло».
- E9. Текст без времени («напомни купить хлеб») → время не найдено (regex), задача «купить хлеб».
- E10. Регистр и «Напомните» / «напомнить» — тоже триггер; «напоминание», «напомнил» — нет.

**Бот**
- B1. Свободный текст «через 2 минуты напомни про лимиты клода» → ответ «Напомню «лимиты клода» 09.11.2026 HH:MM. Повторять?» с кнопками; вопрос «Когда?» не задаётся; после «Один раз» напоминание в БД и в планировщике.
- B2. `/new` → «через 2 минуты напомни про лимиты клода» → сразу вопрос о повторе (без «Когда?»).
- B3. `/new` → «купить хлеб» (без времени) → как раньше, «Когда напомнить?».
- B4. «напомни через 5 минут» → «О чём напомнить?» → «размяться» → вопрос о повторе со временем now+5 мин.
- B5. Свободный «напомни купить хлеб в пятницу вечером» (regex не нашёл) → вызывается Gemini (мок) с текстом и подписью «Текстовая команда»; его время и задача → вопрос о повторе.
- B6. Gemini вернул ошибку → понятный ответ с примерами форматов и `/new`, напоминание не создаётся.
- B7. Текст без слова «напомни» (в т.ч. «встреча через 2 часа») → не напоминание, тихо в контекст (как раньше), Gemini не вызывается.
- B8. Текст в любом FSM-состоянии не перехватывается `on_free_text` (через `dp.feed_update`).
- B9. Задача с HTML («напомни через 2 мин про <b>») экранируется в ответах.
- B10. Весь набор тестов и ruff зелёные; сеть замокана.

## Ограничения (осознанно)
- Числа словами («через две минуты»), «в 9» без минут, «в пятницу» — только через Gemini (для свободного текста); в шаге `/new` без Gemini — бот просто спросит время.
- Если в тексте два времени — берётся первое по порядку приоритета.
