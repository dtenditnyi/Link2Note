# Устойчивость к недоступности Gemini

Статус: **реализовано, ждёт ручной проверки**.

## Задача
Gemini отвечает 503 UNAVAILABLE («high demand») / 429 / таймаут → сейчас бот сразу пишет «Не удалось обработать голосовое» и теряет распознанный текст. Нужно: ретраи с нарастающей паузой, запасная модель, разбор нашим парсером времени, а если и он не справился — сохранить текст, показать его и дать «Повторить» без новой записи.

## Решения владельца (09.11.2026)
- `GEMINI_FALLBACK_MODEL` — по умолчанию пусто (запасная модель выключена), имя задаётся в `.env`.
- Запасной путь (наш парсер → «Я услышал») — **только при недоступности** Gemini (503/500/502/504, 429, 408, таймаут, сбой соединения). Если Gemini ответил, но не понял (`IntentError`) — как сейчас.

## Исследование
- **google-genai 3.0 (установлен) умеет ретраи сам:** `types.HttpRetryOptions(attempts, initial_delay, max_delay, exp_base, jitter, http_status_codes)` — tenacity, экспоненциальная пауза с jitter; по умолчанию повторяет 408, 429, 5xx и `httpx.TimeoutException` / `httpx.ConnectError`. Передаётся в запросе: `GenerateContentConfig(http_options=HttpOptions(retry_options=..., timeout=<мс>))` (`_api_client.retry_args`, проверено по исходникам в `.venv`).
- Ошибки: `errors.ServerError` (5xx) и `errors.ClientError` (4xx), обе — `errors.APIError` с `.code` и `.status`.
- Ретраи идут **внутри** SDK — снаружи момент повторной попытки не виден. Чтобы показать «Gemini перегружен, пробую ещё раз…», делаем 1-ю попытку без ретраев, а при временной ошибке — сообщение и ещё 2 попытки встроенным `HttpRetryOptions` (итого 3; свой цикл ретраев не пишем).
- `HttpOptions.httpx_async_client` позволяет подставить `httpx.AsyncClient(transport=httpx.MockTransport(...))` — ретраи SDK проверяются **настоящим** `genai.Client`, без сети.

## Поток голосового (новый)
1. Whisper → текст (как сейчас).
2. Gemini, основная модель, 1 попытка. Временная ошибка → статус «⏳ Gemini сейчас перегружен, пробую ещё раз…».
3. Основная модель, ещё до 2 попыток (`HttpRetryOptions`: пауза ~1 с → ~2 с, + jitter). Всё ещё временная ошибка и задана `GEMINI_FALLBACK_MODEL` → статус «⏳ Пробую запасную модель…» → 1 попытка на ней.
4. Gemini недоступен → наш парсер (`parse_text_reminder` из text-time-extraction). Нашёл время и задачу → обычное подтверждение «Сохранить / Отмена» с пометкой «(разобрал без Gemini)», повтор — «один раз».
5. Не нашёл → «🎧 Я услышал: «…»» + «Gemini сейчас недоступен» + кнопка «🔁 Повторить» + подсказка «или напиши текстом: «через 20 мин напомни …»». Текст хранится по (chat_id, message_id) 6 ч.
6. «Повторить» → тот же текст снова по шагам 2–5 (без скачивания и Whisper); устарел → «Текст устарел — отправь голосовое ещё раз».

Свободный текст со словом «напомни» (Gemini-ветка из text-time-extraction) получает ретраи и запасную модель автоматически — тот же `IntentParser`.

## План
1. `config.py`: `gemini_fallback_model: str = ""`, `gemini_timeout_s: int = 20`.
2. `services/intent.py`:
   - `LLMUnavailableError` (не `IntentError`) — Gemini недоступен после всех попыток; хранит последний код/причину.
   - `is_transient(err)` — `APIError` с кодом 408/429/500/502/503/504, httpx-таймаут/соединение.
   - `parse(..., on_retry: Callable[[str], Awaitable] | None)` — шаги 2–3; `on_retry("busy")` / `on_retry("fallback")` для статусов.
   - Конфиг запроса: `http_options=HttpOptions(timeout=..., retry_options=...)`; для 1-й попытки `attempts=1`.
3. `services/drafts.py` → общий `TtlStore[T]`; `DraftStore` и новое хранилище текстов голосовых (`TranscriptStore`, TTL 6 ч).
4. `handlers/keyboards.py`: `VoiceRetryCb(mid)`, клавиатура «🔁 Повторить».
5. `handlers/voice.py`: вынести разбор текста в `_process_text(...)` (шаги 2–5), использовать из `on_voice` и нового `on_voice_retry`.
6. `main.py`: передать fallback-модель/таймаут, `transcripts` в workflow_data.
7. Тесты сначала (красные), потом код; `docs/PLAN.md`, `CLAUDE.md` (новые переменные `.env`).

## Критерии приёмки
**Ретраи (G)**
- G1. Настоящий `genai.Client` с mock-транспортом: 503, 503, 200 → результат получен, сделано 3 HTTP-запроса; паузы растут (тест с малым `initial_delay`).
- G2. То же для 429 → 200.
- G3. Таймаут (`httpx.ReadTimeout`) → 200 → результат получен.
- G4. 400 / 403 (неверный ключ) — **не** повторяются (1 запрос) и не считаются недоступностью.
- G5. После первой временной ошибки вызывается `on_retry("busy")` ровно один раз.
- G6. 503 после всех попыток + `GEMINI_FALLBACK_MODEL` задана → 1 запрос на запасную модель (проверяется имя модели), `on_retry("fallback")`; успех → результат.
- G7. Запасная модель не задана → запасной попытки нет, `LLMUnavailableError`.
- G8. Запасная модель тоже 503 → `LLMUnavailableError`.

**Голосовое (V)**
- V9. 503 → статус «Gemini сейчас перегружен, пробую ещё раз…» показан; при успехе ретрая — обычное подтверждение.
- V10. Gemini недоступен, в тексте «напомни через 2 минуты выпить воды» → подтверждение «Сохранить / Отмена» с «(разобрал без Gemini)»; «Сохранить» создаёт напоминание.
- V11. Gemini недоступен, «напомни купить хлеб в пятницу» (время не найдено) → «Я услышал: «…»», кнопка «Повторить», подсказка про текст; напоминание не создано; текст не потерян.
- V12. «Повторить» → разбор того же текста; Whisper и скачивание **не** вызываются повторно; при успехе — подтверждение; снова недоступен — снова экран «Я услышал» с кнопкой.
- V13. «Повторить» для устаревшего/чужого текста → «Текст устарел…», ничего не создаётся.
- V14. Gemini ответил, но не понял (`IntentError`) → как сейчас: «Не понял напоминание: …» (решение владельца).
- V15. Нигде не показывается «Не удалось обработать голосовое» для 503/429/таймаута.
- V16. Контекст к голосовому не теряется при недоступности Gemini (остаётся до успешного разбора Gemini).
- V17. Тексты экранируются (HTML в распознанном тексте).

**Прочее**
- O5. Свободный текст «напомни …» без времени при 503 → ретраи; недоступен → подсказка с форматами (как сейчас), без падения.
- O6. Весь набор тестов и ruff зелёные; сеть замокана (mock-транспорт httpx).

## Время ожидания (худший случай)
3 попытки × таймаут 20 с + паузы ~3 с + запасная модель 20 с ≈ 1,5 мин — пользователь всё это время видит статус. При 503 (быстрый ответ) — несколько секунд.
