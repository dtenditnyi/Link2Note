# Этап 0 — перенос assistant_bot в Link2Note

Статус: **реализовано, ждёт ручной проверки**. Решения владельца — в конце.

## Задача
Перенести все функции старого бота-напоминалки (создание/список/изменение/удаление напоминаний, голос → напоминание, контекст к голосовому) в Link2Note с новой структурой, исправить проблемы из MIGRATION.md и найденные дополнительно, покрыть тестами. Функции конспектов (этап 1+) не трогаем, но маршрутизация уже не должна мешать ссылкам.

## Дополнительно найденные проблемы (сверх MIGRATION.md)
10. **HTML-инъекция:** текст задачи вставляется в сообщения с `parse_mode=HTML` без экранирования — задача `купить <молоко>` роняет отправку (Telegram 400), в т.ч. в момент срабатывания напоминания.
11. **Whisper блокирует event loop:** `model.transcribe()` и чтение генератора сегментов идут синхронно в хендлере — пока идёт расшифровка, бот не отвечает никому, а планировщик не шлёт напоминания.
12. **Ошибка при отправке теряет напоминание:** если `send_message` упал (сеть), задача APScheduler уже израсходована, а статус остаётся `pending` — до перезапуска никто его не повторит.
13. **Хрупкий callback_data:** `split("_")`, а кнопка «Назад» использует русский текст как callback_data. Карточка/удаление сработавшего напоминания возвращает его в работу без явного намерения.
14. Голосовое любой длины уходит в Whisper (на CPU — минуты); нет лимита.

## Исследование (кратко)
- aiogram 3.31 (установлен): `dp.update.outer_middleware(...)` срабатывает до фильтров для всех типов апдейтов — правильное место для фильтра владельца (сообщения **и** callback-кнопки). `CallbackData` (pydantic) вместо разбора строк. Проверено по исходникам в `.venv`.
- APScheduler 3.11 (установлен): для `date`-задач по умолчанию `misfire_grace_time=1` с → задача, опоздавшая больше чем на секунду (лаг loop, сон ПК), молча пропускается. Ставим `misfire_grace_time=None`, а просроченные при старте отправляем сами.
- Хорошие боты-напоминалки: кнопки «отложить» (15 мин / 1 ч / завтра) + «готово» на сработавшем напоминании, только для владельца; отложить можно только несработавшее/свежее; предпросмотр распознанного перед сохранением; при ошибке парсинга — показать поддерживаемые форматы; относительное время («через 2 часа»); повторяющиеся (daily/weekly) обычно отдельной фазой.
- faster-whisper на CPU: `small` int8 — лучший баланс для русского; `base` быстрее, но заметно хуже; `turbo/large-v3` для CPU тяжёлые.

  transcribe.py           Transcriber: ленивая загрузка Whisper, работа в asyncio.to_thread
  intent.py               голос/текст → {task, remind_at} через выбранный LLM (pydantic-схема)

handlers/
  middlewares.py          OwnerOnly (outer, на dp.update)

  context.py              обычный текст без ссылок → память, без ответа (последний роутер)

docker-compose.yml        только bot (без ollama), volumes: data/, whisper_cache

## Критерии приёмки
**Безопасность и маршрутизация**
- A1. Сообщение и callback от `user_id != OWNER_ID` не доходят ни до одного хендлера (хендлер-мок не вызван, бот ничего не отвечает).
- A2. Callback изменения/удаления/snooze с id напоминания, у которого другой `chat_id`, не меняет БД и отвечает «не найдено».
- A3. Текст со ссылкой не попадает в контекст-память и не получает ответа (оставлен для Link2Note).
- A4. Обычный текст без ссылки сохраняется в контекст **без ответного сообщения**; через 15 мин память истекает.
- A5. Текст задачи с `<b>`, `<`, `&` отображается буквально во всех сообщениях (создание, список, карточка, срабатывание).

**Время**
- T1. `HH:MM`, `HH:MM:SS`, `YYYY-MM-DD HH:MM[:SS]` → datetime с tz Europe/Bucharest (всегда aware).
- T2. `HH:MM` раньше текущего времени → завтра; дата в прошлом → `ValueError` с понятным текстом.
- T3. Неверный формат → `ValueError`, сообщение перечисляет форматы.
- T4. Часовой пояс задаётся только в `config.py` (grep `Europe/Bucharest` в коде — 1 место).

**Хранение и планировщик**
- S1. После создания напоминание есть в БД (`pending`, aware ISO) и в планировщике (`reminder-<id>`).
- S2. При срабатывании: сообщение отправлено, статус `sent`; при ошибке отправки — статус остаётся `pending`, повторная попытка через 1 мин (до 3 раз), потом `failed` в логе.
- S3. При старте: будущие `pending` перепланированы; просроченные < 24 ч отправлены сразу с пометкой «⏰ Пропущено, должно было сработать в …»; старше 24 ч → `missed` + одно сводное сообщение (Q4).
- S4. `misfire_grace_time=None` у задач напоминаний.
- S5. Список показывает только `pending`, отсортированные по времени, с датой и временем; пустой → «Нет активных напоминаний».
- S6. Изменение времени: БД и задача обновлены, старая задача удалена; удаление: строка и задача удалены.

**Голос**
- V1. Импорт `handlers.voice` не загружает Whisper; модель грузится один раз при первом голосовом.
- V2. Расшифровка выполняется вне event loop (`asyncio.to_thread`).
- V3. Голосовой файл скачивается во временную папку и удаляется в любом случае (успех/ошибка).
- V4. Голосовое длиннее лимита (по умолчанию 120 с) → отказ без расшифровки.
- V5. Ответ LLM валидируется pydantic-схемой; некорректный JSON, нет полей, время в прошлом → понятная ошибка, напоминание не создаётся.
- V6. Контекст из памяти подмешивается к голосовой команде и очищается после использования.
- V7. Промпт содержит текущее время и не содержит захардкоженных дат-примеров в прошлом (примеры строятся от `now`).

**Прочее**
- O1. `/cancel` в любом состоянии FSM сбрасывает его; вне FSM — ничего не делает.
- O2. `uv run pytest -q` и `uv run ruff check .` — зелёные; сеть/Whisper/LLM замоканы.
- O3. Dockerfile на Python 3.12, зависимости из `pyproject.toml`/`uv.lock`; `docker compose build` проходит (ручная проверка).
- O4. Ручная проверка в Telegram: создать → список → изменить → удалить; голосовое «напомни через 2 минуты выпить воды» → напоминание пришло; перезапуск бота с напоминанием в прошлом → пришло с пометкой.

## Улучшения сверх переноса (все приняты, Q3)
- **Отложить** (S7): на сработавшем напоминании кнопки «+15 мин», «+1 ч», «Завтра 9:00», «✅ Готово».
  - S7a. «+15 мин» → новое время = сейчас + 15 мин, статус `pending`, задача в планировщике; сообщение-напоминание редактируется («Отложено до …»).
  - S7b. «✅ Готово» → статус `done`, кнопки убираются. Повторное нажатие на старой кнопке ничего не ломает («уже выполнено»).
  - S7c. Отложить можно только `sent`/`missed` напоминание своего чата; для повторяющегося — откладывается только текущее срабатывание, расписание не сдвигается.
- **Подтверждение голосового** (V8): «Понял так: <задача>, когда: <время>[, повтор: …]» + «✅ Сохранить» / «❌ Отмена». До «Сохранить» в БД ничего нет. Черновик хранится в памяти (`services/drafts.py`) по ключу (chat_id, message_id сообщения с подтверждением) — у каждого голосового свой; не зависит от FSM; живёт 30 мин; «Отмена» удаляет черновик. Контекст расходуется только при успешном разборе. _(Уточнено по итогам ревью: изначально был один ключ в FSM.)_
- **Относительное время текстом** (T5): `через 20 мин`, `через 2 ч`, `через 1 д`, `через 1 ч 30 мин`, `завтра 9:00`, `послезавтра 18:30`, `сегодня 21:00` (+ сокращения `20m`, `2h`). Остальное — понятная ошибка со списком форматов.
- **Повторяющиеся** (R): колонка `repeat` ∈ `none | daily | weekly`.
  - R1. Создание: после выбора времени — кнопки «Один раз / Каждый день / Каждую неделю»; голосом — LLM возвращает `repeat` («каждый день в 9»).
  - R2. После срабатывания повторяющегося напоминания `remind_at` сдвигается на следующее вхождение (с учётом DST: 9:00 остаётся 9:00 местного времени), статус `pending`, новая задача в планировщике.
  - R3. При старте просроченное повторяющееся: одно сообщение-пропуск (если < 24 ч), затем перенос на ближайшее будущее вхождение — без «залпа» за каждый пропущенный день.
  - R4. В списке и карточке виден повтор (🔁 ежедневно / еженедельно); удаление удаляет всю серию.

## Решения (от владельца, 08.11.2026)
- Q1 LLM для голосовых: **Gemini** (`GEMINI_MODEL` из `.env`, structured output по pydantic-схеме). Контейнер `ollama` и зависимость `ollama` убираем.
- Q2 Модель Whisper: **small**, CPU, int8 (значение по умолчанию в `config.py`).
- Q3 Улучшения: **все четыре** (S7, V8, T5, R).
- Q4 Пропущенные: **только свежие** — опоздание < 24 ч → отправить с пометкой «⏰ Пропущено, должно было сработать в …»; старше → статус `missed`, одно сводное сообщение «Пропущено пока бот был выключен: N» со списком. S3 уточнён соответственно.
